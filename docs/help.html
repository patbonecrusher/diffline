Help

Everything Diffline does, and how to wire it into git.

Compare two files or folders

  • Drop two items on the start window, or on Diffline's Dock icon.
  • Choose File › Compare Files… (⌘O) or Compare Folders… (⇧⌘O) and select two items.
  • In Finder, select two items and choose Services › Compare with Diffline.
  • In Terminal: diffline left.txt right.txt.

Removed lines are tinted red on the left and added lines green on the right. Striped space stands in for lines that exist on only one side, so the rows stay aligned. In a folder comparison, double-click a file to open it side by side.

The narrow strip beside the scroll bar is the change overview: the whole file shrunk to the window's height, with a mark for every change (red removed, green added, blue modified) and a box around the part on screen. Click or drag in it to jump. In a merge, orange marks are conflicts still waiting for a decision. Hide it with View › Show Change Overview (⌥⌘M).

Merge changes

Each change has two arrows in the strip between the panes. The right arrow copies the left version into the right file; the left arrow does the opposite. Edited files show Edited in their header until you save with ⌘S. File › Revert to Saved discards your merges.

Three-way merge

Use this when two people edited the same original file. Choose File › Merge Files… (⌥⌘O) and pick three files: Left (yours), Base (the original) and Right (theirs). Optionally pick where to save the result.

The window shows your version, the merged result and their version. Changes made on only one side are already applied. For each conflict, choose Take Left, Take Right, Both or Base. If you save with conflicts still open, Diffline writes git-style <<<<<<< / ======= / >>>>>>> markers so nothing is lost.

Use Diffline with git

The Homebrew cask installs the diffline command. If you installed the app another way, choose File › Install Command Line Tool… and save it to a folder on your PATH, such as /opt/homebrew/bin. Then run:

git config --global merge.tool diffline
git config --global mergetool.diffline.cmd 'diffline --merge "$BASE" "$LOCAL" "$REMOTE" "$MERGED"'
git config --global mergetool.diffline.trustExitCode false
git config --global diff.tool diffline
git config --global difftool.diffline.cmd 'diffline --wait "$LOCAL" "$REMOTE"'

After a merge stops with conflicts, run git mergetool. Each conflicted file opens in Diffline; resolve it, save, and close the window, and git moves on to the next file. git difftool works the same way for reviewing changes, one file at a time, and git difftool -d opens the whole change set as a folder comparison. In a -d comparison against your working tree, merges you save go straight into your working files.

Options

The Options menu in each window, and Settings (⌘,) for new windows, control whitespace handling (exact, trailing, changes, all), case, blank lines, syntax highlighting and the language used to color the files, font size, tab width and line wrapping.

“Diffline can't read” a file

Diffline runs in the macOS App Sandbox, so it can open only what you give it. The reason appears in the dialog, or when you hover over Can't read in a folder comparison:

  • A link outside the folders Diffline was given. Usually git difftool -d with an older diffline command. Run brew upgrade --cask diffline, or File › Install Command Line Tool… again.
  • Your user account isn't allowed to read it. Check the file in Finder with File › Get Info; files created with sudo or by a container are a common cause.

Something wrong?

Report it on GitHub Issues, with the macOS version and, if you can, two small files that show the problem.
